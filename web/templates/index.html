Arsitektur Sistem & FAQ

Landasan arsitektural komputasi paralel: topologi prosesor heterogen Intel Raptor Lake, dekomposisi spasial baris horizontal, dan mekanisme boundary halo (k=1).

Topologi Prosesor Heterogen

P-Core, E-Core, dan saturasi utas eksekusi

Arsitektur Heterogen

Laptop pengujian menggunakan prosesor generasi ke-13 (Raptor Lake) dengan arsitektur hibrida:

  1. 4 Performance-Cores – hingga 4.6 GHz, Hyper-Threading (8 logical threads), cache L3 besar untuk komputasi berat.
  2. 4 Efficient-Cores – hingga 3.4 GHz, tanpa Hyper-Threading (4 logical threads), untuk efisiensi daya latar belakang.
  3. Total Thread Eksekusi – 12 utas logis, RAM.

Utilisasi thread CPU saat ini – P-Core biru, E-Core ungu.

Mengapa speedup pada P=8 relatif saturasi? Pada P=1, 2, 4, OS mengalokasikan beban kerja pada core performa tinggi (P-Cores). Pada P=8 dan P=12, sistem mulai mengeksekusi worker di E-Cores dan hyper-threads, di mana frekuensi clock lebih rendah (3.4 GHz vs 4.6 GHz) dan terjadi perebutan shared L3 cache. Hal ini membuktikan Hukum Amdahl dan overhead sinkronisasi IPC.

Dekomposisi Baris & Boundary Halo

Partisi baris, trimming batas, dan rekonstruksi

Halo k=1

Dalam operasi konvolusi spasial seperti Gaussian Blur (3×3) dan Sobel (3×3), nilai piksel pada baris batas memerlukan informasi piksel tetangga dari blok di atas atau di bawahnya: 

[ Worker 0 ] -> Baris 0 s/d (H/P - 1) + 1 Baris Halo Bawah (k=1)
================================================= [Boundary Seam]
[ Worker 1 ] -> 1 Baris Halo Atas + Baris H/P s/d (2H/P-1) + 1 Halo Bawah
================================================= [Boundary Seam]
[ Worker P ] -> 1 Baris Halo Atas + Baris ... s/d H-1

Tahapan Eksekusi Bebas Artefak (Artifact-Free)

  1. Pemekaran partisi (Halo Insertion): setiap worker menerima sub-matriks diperluas setinggi (H/P) + 2k baris.
  2. Komputasi konvolusi lokal: worker menerapkan filter tanpa komunikasi antar proses.
  3. Pemangkasan batas (Trimming): baris k atas & bawah dipangkas dari hasil lokal.
  4. Rekonstruksi zero-copy: hasil utuh digabungkan via numpy.vstack() sekuensial.

Verifikasi membuktikan Δmax = 0.000000 (100% bit-identik dengan eksekusi serial).

Panduan Pembelaan Akademik (Evaluasi Dosen)

Jawaban siap pakai untuk sesi evaluasi

Tanya Jawab
› Mengapa efisiensi pada citra kecil (512×512) rendah atau speedup < 1x?
Pada citra 512×512 (beban komputasi sekitar 0.006 detik), waktu untuk serialisasi memori (pickling), partisi matriks, dan pengiriman buffer array melalui IPC (Inter-Process Communication) jauh lebih besar daripada waktu komputasi aritmatika filter itu sendiri. Ini membuktikan prinsip bahwa komputasi paralel hanya memberikan percepatan signifikan jika rasio komputasi terhadap komunikasi (Tcomp / Tcomm) bernilai tinggi.
› Mengapa pengujian menggunakan arsitektur pre-warmed pool?
Pada Windows, multiprocessing menggunakan metode spawn, bukan fork seperti pada Linux. Pembuatan proses Python baru (cold spawn) membutuhkan inisialisasi runtime 1.5–2.5 detik. Jika waktu spawn dimasukkan dalam blok pengukuran, ia mengaburkan pengukuran murni algoritma paralel. Dengan pre-warmed pool, kita mengukur pure algorithmic speedup secara adil.
